# [PRD] 백테스트-실전 공통 판단 코어 구현 요구사항 정의서 v1.0

## 1. 개요 (Background & Objectives)
*   **배경**: 현재 백테스트 엔진과 실전 스크리너가 독립적인 판단 로직을 사용하여 운영 효율성이 떨어지고 결과의 일관성이 보장되지 않음.
*   **목표**: "오늘의 목표 포트폴리오 상태"를 계산하는 공통 코어를 구축하여, 백테스트와 실전이 동일한 의사결정 기준을 공유하게 함.

## 2. 주요 기능 범위 (Feature Scope)

### 2.1 목표 상태 계산 (Target State Calculation)
*   **국면별 자산 배분**: BULL, BEAR, UNSTABLE, PANIC 국면에 따른 현금/헤지 비중 자동 산출.
*   **슬롯 할당 정책**: 가용 자산 비중을 기반으로 롱(Long) 포지션 최대 개수(Slots) 결정.
*   **종목 선정 및 정렬**: 앙상블 점수, 상대 강도를 기준으로 우선순위 부여 및 결정론적 순서 보장.

### 2.2 현재 상태 진단 및 리밸런싱 판정 (Decision Logic)
*   **상태 비교**: 현재 보유 종목 집합과 목표 집합의 차이 분석.
*   **이탈 감지**: 목표 비중과 실제 비중의 차이가 허용 오차(Tolerance)를 벗어나는지 확인.
*   **사유 코드 생성**: `SYMBOL_SET_CHANGED`, `CASH_RATIO_DEVIATION` 등 리밸런싱이 필요한 이유를 구조화된 데이터로 제공.

### 2.3 백테스트 엔진 통합 (Engine Integration)
*   **관측 지점 연결**: 매일의 매매 집행 전 판단 코어를 호출하여 '오늘의 의사결정' 데이터 생성.
*   **의사결정 로깅**: 리밸런싱 여부, 사유, 목표 대비 현재 종목 구성을 CSV 로그에 기록.

## 3. 기술적 상세 사양 (Technical Specifications)

### 3.1 핵심 데이터 구조
*   `TargetPortfolioState`: 목표 국면, 비중, 슬롯, 심볼 리스트.
*   `CurrentPortfolioState`: 실제 보유 종목, 현금 비중, 헤지 상태.
*   `RebalanceDecision`: 판단 결과 필드 (`rebalance_needed`, `rebalance_reason` 등).

### 3.2 정책 명세 (Policy)
*   **슬롯 계산**: `int(max_positions * 가용비중)` (내림 처리로 보수적 운용).
*   **PANIC 예외**: PANIC 국면 시 롱 슬롯을 강제로 0으로 설정하여 신규 진입 차단.
*   **정렬 우선순위**: 1. Score(내림), 2. RS(내림), 3. Symbol(오름).
*   **허용 오차**: 비중 편차 5% 초과 시에만 리밸런싱 사유로 인정.

## 4. 성공 지표 (Success Metrics)
*   **재사용성**: 백테스트 엔진 내부에서 공통 코어 함수 호출 성공.
*   **추적성**: 모든 거래일의 리밸런싱 사유가 로그에서 확인 가능함.
*   **안정성**: 동일 입력에 대해 항상 동일한 목표 상태를 반환함 (Unit Test 통과).

## 5. 단계별 구현 로드맵 (Roadmap)
*   **Phase A**: 목표 상태 계산 순수 함수 및 데이터 구조 구축 (완료).
*   **Phase B**: 현재 상태 비교 및 리밸런싱 판정 계층 추가 (완료).
*   **Phase C**: 백테스트 엔진 얕은 연결 및 통합 검증 (완료).
*   **Phase D**: 실전 스크리너(`run_screener.py`) 동기화 및 주문안 자동 생성 (예정).
