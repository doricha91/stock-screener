# [PRD] MFU7: 유니버스 바스켓 주기 갱신 및 티커 위생 관리 v1.0

## 1. 개요 및 상태 (Context & Status)
- **배경**: 프론트테스트에서 stale 종목이 후보로 노출되는 문제가 확인되었다. 이는 전략 로직보다 유니버스 바스켓과 가격 데이터의 최신성 관리 부재에서 비롯된다.
- **목표**: 바스켓 구성 종목을 주기적으로 갱신하고, stale / inactive 티커를 구분하여 프론트테스트와 운영 리포트의 품질을 높인다.
- **상태**: 초안 / 일부 선행 구현 완료
  - 완료: front-test stale filter, 후보별 필터 진단
  - 미완료: 바스켓 주기 갱신, universe snapshot, 수집 실패 종목 관리
## 2. 기능 요구사항 (Requirements)

### 2.1 바스켓 갱신
- SP500, NASDAQ100 등 주요 유니버스 바스켓을 주기적으로 재수집해야 한다.
- 각 실행 시점에 다음 정보를 산출해야 한다.
  - 신규 편입 종목
  - 바스켓 이탈 종목
  - 기존 유지 종목
- 최소 산출물은 운영자가 읽을 수 있는 요약 리포트여야 한다.

### 2.2 stale / inactive 의심 감지
- `data_date` 대비 최신 가격이 일정 기준보다 오래된 종목을 stale로 분류한다.
- 반복 수집 실패 또는 데이터 없음 종목은 `inactive/delisted 의심`으로 표시한다.
- 단, MVP에서는 DB에 inactive 상태를 저장하지 않는다.
- stale 감지는 최소 다음 정보를 포함해야 한다.
  - symbol
  - latest_price_date
  - stale_days
  - 소속 바스켓
- 수집 시 `df.empty` 또는 반복 실패가 발생하는 종목은 별도 목록으로 분리해야 한다.

### 2.3 프론트테스트 보호
- stale 종목은 front-test 최종 후보군에서 제외되어야 한다.
- 제외 사유는 daily action plan 리포트에 표시되어야 한다.
- 단, screener 자체의 전역 동작은 별도 단계에서 다룬다.

### 2.4 관리 리포트
- 바스켓 갱신 결과와 stale 티커 현황을 하나의 운영 리포트로 확인 가능해야 한다.
- 리포트는 최소 아래 섹션을 포함해야 한다.
  - 바스켓 변경 요약
  - stale 티커 목록
  - 수집 실패 티커 목록
  - 수동 검토 필요 항목

## 3. 범위 (Scope)

### 3.1 포함 사항 (In-Scope)
- 유니버스 바스켓 주기 갱신 워크플로우 정의
- stale / inactive 후보 감지 기준 정의
- 프론트테스트 출력 보호 정책
- 운영 리포트 형식 정의

### 3.2 제외 사항 (Out-of-Scope)
- DB 스키마 변경
- 백테스트 전 구간 membership 재구축
- delisted 종목 자동 삭제
- 거래일 캘린더 기반 정밀 stale 계산
- 브로커/주문 자동화

## 4. 사용자 시나리오 (User Scenarios)
- 운영자는 주간 바스켓 갱신 실행 후 “어떤 종목이 새로 들어왔고 무엇이 빠졌는지”를 확인한다.
- 운영자는 stale 티커 목록을 보고 데이터 공급 문제인지 실제 상장폐지 의심인지 구분한다.
- 프론트테스트 실행 시 stale 후보가 최종 후보군에서 자동 제외되고, 리포트에서 제외 사유를 확인한다.

## 5. 수용 기준 (Acceptance)
- 바스켓 갱신 리포트에서 신규 편입 / 이탈 / stale 목록이 구분된다.
- 운영자는 특정 종목이 왜 후보에서 제외되었는지 리포트만으로 설명 가능하다.
- 유니버스 갱신 작업이 다른 전략 정책(`score_threshold`, `rs_val > 0`, cash policy)을 변경하지 않는다.
- 바스켓 갱신 dry-run 실행 시 added / removed / kept 수가 출력된다.
- DB를 수정하지 않고도 현재 tickers와 최신 바스켓의 차이를 확인할 수 있다.
- DAY 같은 removed 가능 종목이 active universe 후보에서 제외 가능한 상태로 식별된다.

## 6. 완료 메모 및 후속 작업 (Closeout / Next)
