# [IDEA] 백테스트-실전 동기화 및 공통 판단 코어 (MFU1)

1) 누가 쓸 건지 (User / Persona)
- 시스템 트레이딩 운용자 (백테스트와 실전의 괴리를 줄이고 싶은 사용자)
- 전략 개발자 (본인이 짠 로직이 실전에서도 동일하게 작동함을 보장받고 싶은 개발자)

2) 어디서 쓰는지 (Market / Venue / Product)
- 자산군: 미국 주식 (NASDAQ100 등)
- 시스템 단계: 백테스트 엔진(backtest_engine) 및 실전 스크리너(run_screener) 공통

3) 비슷한 서비스/전략이 있는지 (Benchmark)
- 기존의 독립적 스크리닝 방식: 엔진과 스크리너가 각자 로직을 중복 구현함
- 개선 방향: 'Single Source of Truth (SSOT)' 기반의 의사결정 코어 분리

4) 반드시 필요한 기능 (Must-have)
- 공통 판단 로직 (Decision Core)
    - 국면별 목표 포트폴리오 상태(Target State) 계산
    - 현재 상태(Current State)와 목표 상태의 차이 분석
    - 리밸런싱 필요 여부 및 구체적 사유(Reason Code) 산출
- 백테스트 통합
    - 매일 아침의 의사결정 과정을 관측 가능한 로그로 남기기
    - 기존 매매 로직과 공통 판단 코어의 병행 검증

5) 절대 필요 없는 기능 (Won’t-have)
- 이번 단계에서의 실전 주문 자동 집행 (판단 계층 구축에 집중)
- 복잡한 최적화 알고리즘 (기존 정책의 명시적 수식화 우선)

6) 성공 기준 (아이디어 단계에서 수치로 정하기)
- 동기화 오류 제로: 동일 데이터 입력 시 엔진과 코어의 산출물 일치 여부
- 관측 가능성 확보: 백테스트 로그 내 리밸런싱 사유 기록 100% 달성
- 정책 명확성: 모든 슬롯 및 비중 계산 로직의 문서화 및 코드 반영
