# MFU 6: Dynamic Regime Parameter Routing PRD v1.0
**Project Iron Dome: 국면별 파라미터 동적 라우팅 시스템**

## 1. 개요 (Executive Summary)
본 문서는 최적화 엔진(`run_optimizer.py`)에서 생성된 파라미터 그리드가 시장 국면별 세부 설정(`REGIME_RULES`)에 정확히 전달되지 않는 기술적 결함을 해결하기 위한 요구사항을 정의한다. 이를 통해 사용자는 각 시장 국면(BULL, BEAR 등)에 특화된 파라미터를 독립적으로 최적화하고 실험할 수 있다.

## 2. 목표 (Goals)
*   **최적화 정밀도 향상**: 국면별로 서로 다른 현금 비중, 헤지 비중, 진입 문턱 등을 개별적으로 튜닝할 수 있는 환경 제공.
*   **구조적 자동화**: 수동으로 `config.py`를 수정하지 않고도 파라미터 그리드 명명 규칙만으로 내부 중첩 구조에 값을 주입.
*   **실험 일관성**: 전역 변수와 국면 변수가 혼재된 상황에서도 명확한 우선순위를 부여하여 실험 결과의 신뢰성 확보.

## 3. 사용자 요구사항 (User Stories)
*   **국면별 변수 명시**: "그리드에 `BEAR_target_cash_ratio`와 `BULL_target_cash_ratio`를 동시에 넣고, 약세장과 강세장에서 각각 최적의 현금 비중을 한 번의 실행으로 찾고 싶다."
*   **우선순위 보장**: "내가 특정 국면 변수를 명시했다면, 전역 설정보다 해당 값이 우선적으로 적용되어야 한다."
*   **기본값 유지**: "실험하지 않는 항목은 `config.py`에 정의된 검증된 기본값을 따라가서 실험의 변수를 최소화하고 싶다."

## 4. 핵심 기능 요구사항 (Functional Requirements)
*   **규격화된 명명 규칙 지원**: `{REGIME_UPPER}_{parameter_name}` 형식의 키 값을 국면 전용 변수로 인식.
*   **동적 구조 재구성**: 주입된 평면(Flat) 데이터를 시스템 내부의 중첩된(Nested) `REGIME_RULES` 딕셔너리로 자동 라우팅.
*   **계층적 오버라이드 시스템**: 
    - 1순위: 국면 전용 오버라이드 (예: `BEAR_...`)
    - 2순위: 전역 오버라이드 (예: `target_cash_ratio`)
    - 3순위: `config.py` 기본값
*   **대상 변수 제한 (Scope Control)**: 시스템 안정성을 위해 지정된 5대 핵심 변수만 라우팅 허용.

## 5. 성공 기준
*   `run_optimizer.py` 실행 시 국면별 변수(예: `BEAR_hedge_ratio`)가 백테스트 로그에 정확히 반영됨.
*   국면별 변수 조합 실험 시, 각 국면 구간에서 의도한 파라미터 변화가 관측됨.
