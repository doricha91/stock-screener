# 🛡️ 프론트테스트 운영 표준 절차서 (Front-test SOP)
> **목적**: 시스템의 전략 지시와 인간 운영자의 집행을 일치시키고, 데이터를 누락 없이 축적하여 전략을 개선합니다.

---

## 🌅 Phase 1: 아침 루틴 (Pre-Market)
**시점**: 매일 오전 08:00 ~ 09:00 (장 개장 전)

1. **시장 데이터 업데이트**: (본인의 데이터 수집 스크립트 실행)
2. **시스템 점검 및 지시서 생성**: 터미널을 열고 아래 명령어를 실행합니다.
   ```bash
   python scripts/run_front_test.py
   ```
3. **지시서 확인**: `outputs/front_test/` 폴더에 생성된 `daily_action_plan_YYYYMMDD.md` 파일을 엽니다.
   - **[1. 오늘의 국면]**을 확인하여 심리적 대비를 합니다.
   - **[4. 확정 매매 지시]**를 확인하여 오늘 매수/매도할 종목과 수량을 파악합니다.

> [!IMPORTANT]
> **데이터 최신성 경고(BLOCKED)**가 뜬다면, 데이터 수집 스크립트가 정상 작동했는지 먼저 확인하십시오. 과거 데이터로 매매하는 것은 금지됩니다.

---

## 💹 Phase 2: 장중 루틴 (Market Open)
**시점**: 미국 시장 개장 중

1. **HTS 시세 알람 설정**: 
   - 지시서의 **[3. 실시간 조건부 매도 감시 (Trailing Stop)]** 섹션에 있는 모든 종목의 **Stop Price**를 HTS/MTS 시세 알람으로 등록합니다.
2. **주문 집행**:
   - **장 초반**: [4. 확정 매매 지시]에 따라 주문을 넣습니다. (가급적 지정가 주문 권장)
   - **장 중**: 시세 알람이 울리면(Trailing Stop 터치) 이유 여하를 불문하고 **즉시 전량 매도**합니다.

---

## 🌙 Phase 3: 야간 마감 루틴 (Post-Market)
**시점**: 장 마감 후 또는 퇴근 후 (가장 중요한 단계)

1. **실행 기록(Journal) 기입**:
   - 아침에 열었던 `daily_action_plan_YYYYMMDD.md` 파일 하단의 **[5. 📝 프론트테스트 실행 기록]** 표를 찾습니다.
   - `[ ]`로 비워진 `Act_Shares`, `Act_Price`, `Reason` 칸을 실제 체결 수치로 채웁니다.
   - **주의**: 하나라도 빈칸(`[ ]`)이 있으면 마감이 진행되지 않습니다. 매매가 없었다면 그대로 두어도 되나, '추천'이 있었는데 안 샀다면 사유를 적어야 합니다.

2. **시스템 동기화 (EOD Update)**:
   - 터미널에서 마감 스크립트를 실행합니다.
   ```bash
   python scripts/run_eod_update.py
   ```
   - **현금 입력**: "오늘 장 마감 기준 실제 계좌의 총 현금(Cash)을 입력하세요" 프롬프트가 뜨면 HTS상의 **최종 예수금**을 입력합니다. (팻핑거 방어 로직이 작동 중이므로 오타에 안심하세요.)

> [!WARNING]
> 이 단계를 건너뛰면 내일 아침 시스템이 오늘의 매매 결과와 최고가 갱신을 인지하지 못해 **잘못된 지시**를 내리게 됩니다. 피곤하더라도 반드시 실행하십시오.

---

## 📊 Phase 4: 주말 루틴 (Weekend Review)
**시점**: 매주 토요일 또는 일요일

1. **주간 리뷰 리포트 생성**:
   ```bash
   python scripts/run_review.py --days 7
   ```
2. **리포트 분석**: `outputs/front_test/weekly_review_YYYYMMDD.md`를 읽습니다.
   - **준수율(Compliance)**이 B등급 이하라면 `MANUAL_SKIP` 사유를 복기합니다.
   - **슬리피지(Slippage)**가 0.5% 이상이라면 시장가 주문 대신 지정가 주문 비중을 높이는 것을 검토합니다.

---

## 🆘 Appendix: 트러블슈팅
- **팻핑거 경고 발생**: 입력한 현금이 예상치와 10% 이상 차이 날 때 발생합니다. 오타라면 `n`을 누르고 다시 입력하고, 배당금/입금 등으로 인한 실제 차이라면 `y`를 눌러 강제 동기화하십시오.
- **데이터 4일 초과 차단**: 연휴가 아닌데 이 에러가 뜬다면 DB 업데이트가 누락된 것입니다. `data_processor`를 먼저 실행하십시오.
- **마크다운 파싱 에러**: 표의 파이프(`|`) 기호가 깨지지 않았는지 확인하십시오.
