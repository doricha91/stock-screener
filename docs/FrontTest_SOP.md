# 📋 Front-Test 표준 운영 절차 (Front-test SOP)
**StockScreener: 실전 운용 및 성과 검증 가이드**

> **목적**: 백테스트를 통해 검증된 로직을 실제 시장에 적용하여, 데이터의 정합성과 전략의 유효성을 실시간으로 평가하고 기록합니다.

---

## 🌅 Phase 1: 장 시작 전 루틴 (Pre-Market)
**수행 시간: 08:00 ~ 09:00 (장 시작 전)**

1.  **데이터 업데이트**: (`run_eod_update.py`를 통해 전일 마감이 완료된 상태여야 함)
2.  **매매 지시서 생성**: 터미널에서 아래 명령을 실행합니다.
    ```powershell
    $env:PYTHONPATH="."; python scripts/run_front_test.py
    ```
3.  **지시서 확인**: `outputs/front_test/daily_action_plan_YYYYMMDD.md` 파일을 읽습니다.
    - **[1. 오늘의 국면]**: 현재 시장이 BULL/BEAR/PANIC 중 무엇인지 확인합니다.
    - **[3. 실시간 감시]**: 보유 종목의 **Trailing Stop** 가격을 확인합니다.
    - **[4. 확정 매매]**: 장 시작과 동시에 실행할 `BUY`, `SELL`, `SWITCH` 종목을 확인합니다.

> [!IMPORTANT]
> **데이터 지연 경고(BLOCKED)**가 뜨면, 데이터 수집 스크립트가 전일 데이터를 모두 가져왔는지 먼저 확인하십시오. 낡은 데이터로 매매하는 것은 금지됩니다.

---

## 📉 Phase 2: 장중 루틴 (Market Open)
**수행 시간: 09:30 ~ 15:30 (장중 실시간 대응)**

1.  **HTS 자동 감시 설정**:
    - 지시서의 **[Trailing Stop]** 가격을 확인하여 보유 종목의 '자동 매도(스탑로스)' 주문을 HTS/MTS에 미리 등록합니다.
2.  **주문 집행**:
    - **확정 매매 종목**: 장 시작 직후 시장가 또는 지정가로 주문을 넣습니다.
    - **능동적 스위칭(Active Switching)**: 기존 종목(SWITCH_OUT)을 팔고 신규 종목(SWITCH_IN)을 사는 지시가 있다면, 매도 체결 후 확보된 현금으로 매수를 진행합니다.
3.  **원칙 준수**: 장중 주가가 요동치더라도 시스템이 정해준 `Stop Price` 이탈 전까지는 **임의 매도를 금지**합니다.

---

## 🌃 Phase 3: 장 마감 후 마감 (Post-Market)
**수행 시간: 장 마감 직후 (가장 중요한 단계)**

1.  **실행 기록 작성**:
    - 아침에 열어둔 `Daily Action Plan` 하단의 **기록 템플릿(Journal)**을 채웁니다.
    - `Act_Shares`(실제 수량), `Act_Price`(실제 단가), `Reason`(사유)을 정확히 기입합니다.
2.  **시스템 동기화 (EOD Update)**:
    - 터미널에서 마감 스크립트를 실행합니다.
    ```powershell
    $env:PYTHONPATH="."; python scripts/run_eod_update.py
    ```
    - **예수금 동기화**: 스크립트 안내에 따라 현재 HTS의 **실제 예수금(Cash)**을 입력합니다. (배당금, 이자 등으로 인한 미세한 차이를 보정합니다.)

> [!WARNING]
> 이 단계를 건너뛰면 내일 아침 계획에서 **현금 비중 위반**이나 **보유 종목 불일치** 오류가 발생하여 전체 테스트 신뢰도가 하락합니다.

---

## 📊 Phase 4: 주간 성과 복기 (Weekend Review)
**수행 시간: 매주 주말**

1.  **리뷰 리포트 생성**:
    ```powershell
    $env:PYTHONPATH="."; python scripts/run_review.py --days 7
    ```
2.  **분석 포인트**:
    - **준수율(Compliance)**: 시스템의 지시를 얼마나 정확히 따랐는지 검토합니다.
    - **슬립이지(Slippage)**: 예상 단가와 실제 체결가 사이의 괴리를 분석하여 주문 방식을 개선합니다.
    - **샤프 지수 변화**: 실전 운영 후 포트폴리오의 변동성 대비 수익률이 개선되고 있는지 확인합니다.

---

## 💡 핵심 용어 및 활용 팁

| 용어 | 설명 | 활용 방법 |
| :--- | :--- | :--- |
| **Market Regime** | 시장 상태 (BULL, BEAR 등) | 국면에 따라 현금 비중이 자동 조절됩니다. |
| **Active Switching** | 능동적 종목 교체 (MFU 5) | "A를 팔고 B를 사라"는 지시는 최상위 모멘텀 유지를 위함입니다. |
| **Trailing Stop** | ATR 기반 동적 손절매 | 주가가 오를수록 손절가도 따라 올라가며 수익을 보존합니다. |
| **Reason Code** | 매매 사유 코드 | `INSUFFICIENT_BP`(현금부족) 발생 시 전략적 조절이 필요합니다. |

## 🛠️ 트러블슈팅

- **예수금 오차**: 실제 계좌와 시스템 상의 현금이 10% 이상 차이 날 경우, `run_eod_update.py`를 통해 즉시 보정하십시오.
- **데이터 중복**: 같은 날짜에 계획이 두 번 생성되었다면 `outputs/front_test/` 폴더의 중복 파일을 삭제하고 다시 실행하십시오.
